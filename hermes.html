Omo Space for Hermes

Every Hermes profile gets a desk in your Omo Space world: its lamp lights while the agent works, and a board on the wall shows what every session is doing.

Set it up ↓ What it never does What is Omo Space? →

Honest status. A release candidate: the repository is not public yet. Desks and the Board wall work with today's Omo Space; live lamps, Board activity and in-game notices need an Omo Space bridge update that is not released yet.

At a glance

Three things it adds

A desk for every profile

hermes omo world reads your profiles and builds Hermes HQ: a Hermes Computer desk for each one, its name on a plate.

One board for every session

CLI, Telegram, cron jobs, subagents: what each one is doing right now, on a wall in the hall.

Notices while you play

An agent can send you a short note with omo_notify. It shows in the corner while you walk around.

Setup

Four steps

For people who already run Hermes (0.22.3 or newer). The plugin asks before it changes anything.

  1. Install Omo Space and open a world once

    Its bridge starts with the world; the plugin talks only to that, on this computer. Omo Space install steps →

  2. Add the plugin to Hermes

    Coming soon One line, once the repository is public:

    hermes plugins install omoresearch/hermes-omo-space --enable

    Today, if you have the plugin folder

    cp -r omo-space ~/.hermes/plugins/omo-space
hermes plugins enable omo-space

    For another profile: ~/.hermes/profiles/<profile>/plugins/ and hermes -p <profile> plugins enable omo-space.

  3. Run the checklist

    hermes omo setup

    It finds your Omo bridge, shows which profiles have the plugin on and prints the exact commands for the rest. --enable-all runs them after one y/N prompt.

  4. Build Hermes HQ in your world

    Terminal

    hermes omo world --install "Omo World"

    In game, standing in an open, flat area

    /reload
/function hermes_hq:preview
/function hermes_hq:build

    The preview outlines the hall with particles; green sparks mark the door. Several worlds? --list-worlds shows their names.

That's it. Chat with Hermes anywhere: the CLI, Telegram, a desk in the world. Desks light up and the Board fills in.

In the world

What you'll see

works with today's Omo Spaceneeds the next Omo Space bridge

Desks, one per profile

Each desk is a Hermes Computer set to that profile, with its name on a plate. --max-desks caps the hall (48 by default).

Status lamps

A desk's lamp lights while its agent thinks or runs a tool, so you can see from across the hall who is busy.

The Hermes Board

Every card says what its agent is doing: thinking, running terminal 12s, idle · 14 turns. Past 24 live workspaces it switches to compact cards, so one wall still shows them all.

Elsewhere

Sessions with no desk are listed with their platform: a Telegram chat on the gateway, a cron job, a plain terminal, a subagent.

In-game notices

When an agent calls omo_notify, up to three cards show top left for about five seconds, the profile name in gold. They only draw when no screen is open.

/omonotices off
hide them
/omonotices on
bring them back
/omonotices test
show one now

For your agents

Your agents know where they are

omo_status
A read-only tool: is Omo Space running, what is on the Board, and where this conversation lives in the world.
omo_notify
Sends a short in-game notice: {text, level?} with level info, success or warn. At most 140 characters; anything that looks like a secret is masked.
/omo
A slash command for you: one paragraph on where this chat is in the world.

Both tools are in the toolset omo. Turn on notify_on_finish and the plugin also sends a notice when a turn that took more than a minute ends.

Privacy

What it never does

Nothing leaves your computer. The whole plugin is a small activity log that your own world reads.

  • Metadata only. Event kinds, tool names, timings, model and platform names. Never message text, tool arguments or results. The one exception is omo_notify text, capped and with secrets masked.
  • Loopback only. Its only network calls are GET /health and GET /board.json to your Omo bridge on 127.0.0.1. Other addresses are refused; hooks never touch the network.
  • Not someone else's bridge. On a shared Linux machine it checks that the bridge port is yours, and never queries another user's.
  • No secrets, telemetry or accounts. It never opens .env, auth.json, state.db, logs or session files.
  • Nothing running in the background. No threads, no daemons. It never approves or blocks a tool, injects context or patches Hermes.
  • Asks first. It writes only its own folder in the profile, and hermes omo setup runs commands only after a y/N prompt that defaults to No.

CLI reference
hermes omo setup [--enable-all] [--non-interactive] [--json]
The guided checklist. Without a terminal (cron, gateway, CI) it only prints the checklist and exits 0.
hermes omo status [--json]
A doctor: the bridge on the configured URL, the feed folder, the age of the last event, which profiles have a feed, and one next step.
hermes omo feed [-n N] [--json] [--follow]
Print or follow this profile's feed.
hermes omo world [--install [WORLD] | --out DIR | --zip] [--list-worlds] [--dry-run]
Generate the Hermes HQ datapack. --install writes only <world>/datapacks/hermes_hq/ and needs --force to replace it. --profiles, --exclude and --max-desks choose the desks; --bridge-port sets the Board wall's port.
/function hermes_hq:info · /function hermes_hq:clear
In game: list the desks, or remove the hall again (the white floor stays).
Settings

In plugins.entries.omo-space.settings. Read live: no restart needed.

feed on by default
Write the activity feed.
bridge_url empty by default
Loopback only. Empty means http://127.0.0.1:$OMO_PORT, or port 8780.
notify_on_finish off by default
Send a notice when a turn that took more than 60 seconds ends.
hermes config set plugins.entries.omo-space.settings.notify_on_finish true
Troubleshooting
The Board shows nothing, but hermes omo feed has events
Your Omo bridge predates Hermes feed support; hermes omo status says so. Update Omo Space once a release with feed support is out.
The Board shows nothing and the feed is empty
The plugin is not enabled in that profile (hermes omo setup lists them), or feed is set to false.
hermes omo status says the bridge is not yours
On a shared machine port 8780 can be another user's bridge. hermes omo setup finds yours, or set bridge_url to http://127.0.0.1:<port>.
Changes don't show up after updating the plugin
A running gateway keeps the plugin it loaded. In each profile run hermes plugins disable omo-space, then hermes plugins enable omo-space.
No notices in game
Type /omonotices on; /omonotices test shows one. Notices only draw when no screen is open.
world --install says the datapack already exists
Add --force; only <world>/datapacks/hermes_hq/ is replaced. Then /reload in game.
Requirements and status
  • Hermes Agent 0.22.3 or newer, the first release with every hook the plugin uses. Checked with hermes plugins validate and hermes plugins doctor on 0.22.5.
  • Omo Space, tested on Linux. The plugin itself is stdlib-only Python 3.11+; Omo Space's macOS and Windows builds are new.
  • v0.1.0, release candidate. The repository is not public yet and a Hermes plugin catalog listing is pending. A community plugin by Omo Research, MIT licensed.
  • Still to come: Omo Space's feed-aware bridge and in-game notices are built and tested on a branch, not in a release yet.
