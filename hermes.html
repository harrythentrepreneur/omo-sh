Omo Space for Hermes

Your whole Hermes system, as a building. Every profile gets a desk, a lamp lights while an agent works, and a board on the wall says what each session is doing.

A Hermes Agent plugin, omo-space, for people who already run Hermes: several profiles, CLI and gateway chats, subagents, cron. It writes a small, metadata-only activity feed that your local Omo Space world reads. Nothing leaves your computer.

In 30 seconds

  • A desk per profile. hermes omo world reads your profiles and writes a Minecraft datapack, Hermes HQ: one Hermes Computer desk per profile plus a Hermes Board wall, built with one /function.
  • Lamps and a live board. Desk lamps light up while an agent thinks or runs a tool. The Board shows what every session is doing, and lists the ones that live outside the world (Telegram and other gateway chats, cron jobs, plain terminals, subagents) under Elsewhere.
  • Notices while you play. An agent can send you a short message with omo_notify; it pops up in the corner of the screen while you walk around.
  • One setup command. hermes omo setup finds your Omo bridge, shows which profiles have the plugin on, and prints the exact commands for the rest.

Honest status: the plugin is a v0.1.0 release candidate and its repository is not public yet. The Board activity, Elsewhere, lamps and notices also need an Omo Space bridge with Hermes feed support. That support is built and tested on an Omo Space branch and is not in a released Omo Space yet; today's Omo Space shows the desks and the Board, without the activity.

01

What you see

The Board is a web page the Omo bridge serves, shown on a web wall in your world. With the plugin on, each card says what its agent is doing right now: thinking, running terminal 12s, or idle · 14 turns. Sessions that have no desk are listed under Elsewhere with their platform: a Telegram chat on the gateway, a cron job, a subagent. With more than 24 live workspaces it switches to compact cards so one wall still shows them all.

In the world itself:

  • Desks per profile. Each desk is a preset Hermes Computer in that profile, with its name on a plate. On our machine, with 47 profiles, the generated hall is 57 × 8 × 43 blocks. --max-desks caps it (48 by default).
  • Status lamps light up while that desk's agent thinks or runs a tool.
  • The Hermes Board on the hall's wall, with live activity, Elsewhere and Messages.
  • In-game notices. When an agent calls omo_notify, up to three cards show top left for about five seconds, with the profile name in gold. They only show when no screen is open. /omonotices off hides them, /omonotices on brings them back, /omonotices test shows one.

02

Setup

You already run Hermes. Three commands in a terminal, three in the game.

  1. Install Omo Space and open a world once, so its bridge is running. Follow the Omo Space install steps.
  2. Install the plugin. The one-line install works once the repository is public: 
    hermes plugins install omoresearch/hermes-omo-space --enable

    The repository is not public yet. Until then, if you have the plugin folder, copy it into your profile's plugins folder and enable it:

    cp -r omo-space ~/.hermes/plugins/omo-space
hermes plugins enable omo-space

    For another profile use its own folder, ~/.hermes/profiles/<profile>/plugins/, and hermes -p <profile> plugins enable omo-space.

  3. Run the checklist. It asks before it changes anything. 
    hermes omo setup

    hermes omo setup --enable-all lists the enable command for every profile and runs them after one y/N prompt.

  4. Put Hermes HQ in your world. If you have more than one world, name it (--list-worlds shows them). 
    hermes omo world --install "Omo World"
  5. Build it in game. Stand in an open, flat area, then: 
    /reload
/function hermes_hq:preview
/function hermes_hq:build

    The preview shows the outline with particles; green sparks mark the door. /function hermes_hq:info lists the desks, and /function hermes_hq:clear removes the hall again (the white floor stays).

  6. Chat with Hermes anywhere. In the CLI, on Telegram, from a desk in the world. Desks light up and the Board fills in.

04

For your agents

NameWhat it does
omo_statusRead-only tool. Is Omo Space running, what is on the board, and where this conversation lives.
omo_notifyQueues a short in-game notice: {text, level?}, level info, success or warn. At most 140 characters; anything that looks like a secret is masked.
/omoSlash command: a one-paragraph answer to "where is this conversation in the world?"

Both tools are in the toolset omo. With the setting notify_on_finish on, the plugin also queues a notice when a turn that took more than 60 seconds ends.

05

CLI reference

hermes omo setup [--enable-all] [--non-interactive] [--json]
The guided checklist. Without a terminal (cron, gateway, CI) it only prints the checklist and exits 0.
hermes omo status [--json]
A doctor: the bridge on the configured URL, the feed dir and marker, the age of the last event, which profiles have a feed, and one next step.
hermes omo feed [-n N] [--json] [--follow]
Print or follow this profile's feed.
hermes omo world [--install [WORLD] | --out DIR | --zip] [--list-worlds] [--dry-run]
Generate the Hermes HQ datapack. --install writes only <world>/datapacks/hermes_hq/ and refuses to replace it without --force. --profiles, --exclude and --max-desks choose the desks; --bridge-port sets the Board wall's port.

Settings live in plugins.entries.omo-space.settings: feed (default on), bridge_url (loopback only; empty means $OMO_PORT or 8780) and notify_on_finish (default off). They are read live, with no restart.

06

Privacy, and what it never does

  • Metadata only. The feed holds event kinds, tool names, counters, durations, timestamps, model and platform names, API status codes and kanban task ids. Never message text, tool arguments, tool results, error messages or subagent goals. The one exception is omo_notify text: capped at 140 characters, control characters stripped, secrets masked.
  • Loopback only. The only network calls are GET /health and GET /board.json to your Omo bridge on 127.0.0.1, localhost or ::1, with a 1.5 s timeout. A non-loopback bridge_url is refused, proxies are ignored, redirects are refused. Hooks never touch the network.
  • Not someone else's bridge. On a shared Linux machine it checks that the process on the bridge port is yours, and never queries another user's bridge.
  • No secrets, no telemetry, no accounts. It never opens .env, auth.json, state.db, logs, session files or the Omo bridge token. Nothing is reported anywhere.
  • No background processes. No threads, no daemons. Hooks never approve or block a tool, never inject context and never patch Hermes.
  • Its own data dir. It writes only to its own folder in the active profile (dir 0700, files 0600 on Linux and macOS), bounded: the event log rotates at 512 KiB. hermes omo world writes only where you tell it.
  • Asks first. hermes omo setup runs hermes commands only after a y/N prompt that defaults to No, and never edits config.yaml itself.

07

Troubleshooting

You seeDo this
hermes omo status says the bridge is not yoursOn a shared machine port 8780 can belong to another user's Omo bridge. Run hermes omo setup to find yours, or hermes config set plugins.entries.omo-space.settings.bridge_url http://127.0.0.1:<port>.
Changes don't show up after updating the pluginA running gateway keeps the plugin it loaded. Run hermes plugins disable omo-space, then hermes plugins enable omo-space, in each profile.
The Board shows nothing, but hermes omo feed has eventsYour Omo bridge predates Hermes feed support; hermes omo status says so. Update Omo Space once a release with feed support is out.
The Board shows nothing and the feed is emptyThe plugin is not enabled in that profile (hermes omo setup lists them), or feed is set to false.
No notices in gameType /omonotices on; /omonotices test shows one. Notices only draw when no screen is open.
world --install says the datapack already existsAdd --force; only <world>/datapacks/hermes_hq/ is replaced. Run /reload in game.

08

Requirements and status

  • Hermes Agent 0.22.3 or newer, the first release with every hook the plugin uses. Validated with hermes plugins validate and hermes plugins doctor on 0.22.5.
  • Omo Space, tested on Linux. The plugin itself is cross-platform (stdlib only, Python 3.11+); Omo Space's macOS and Windows builds are new.
  • Status: v0.1.0, release candidate. The repository is not public yet, and a listing in the Hermes plugin catalog is pending. It is a community plugin by Omo Research, not an official or endorsed one.
  • Still to come: Omo Space's feed-aware bridge and in-game notices are on a branch, not in a release yet, and we are still capturing photos of a generated Hermes HQ hall.
