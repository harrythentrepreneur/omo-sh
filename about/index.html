01 / Questions

What we want to understand

These are directions for inquiry, not claims that the work is complete.

Voice

When does an agent feel present?

How do timing, interruption, tone, and turn-taking change an agent from a tool you command into something you can think alongside?

Space

Can place replace the menu?

Could rooms, distance, movement, and orientation make complex agent systems easier to understand than tabs, lists, and chat threads?

Agency

What should remain local?

Which interactions become more private, resilient, and immediate when perception and inference happen on the hardware around us?

02 / Environment

Why Minecraft is on the map

Minecraft turns abstract questions about agents into visible, shared situations. An agent has a position, limited perception, tools, consequences, and other people nearby. That makes the world useful for thinking about more than task completion: how an agent remembers a place, explains an action, recovers from a mistake, takes a spoken instruction, or earns enough trust to remain present.

01

Presence, not just performance

Study whether timing, movement, attention, and voice make an agent legible as a participant in a shared world.

02

Memory with a location

Explore how places, objects, and changes to the world can make an agent's memory observable instead of hidden in a transcript.

03

Cooperation under uncertainty

Ask how an agent should clarify intent, communicate limits, and recover when a long sequence of actions stops matching the world.

03 / Method

How a question becomes research

01

Frame a question

Define the human behavior or interaction we want to understand—not a feature we want to justify.

02

Build the smallest environment

Create a focused prototype that makes the question observable in use.

03

Use it in the world

Document what feels natural, what breaks, and where our assumptions were wrong.

04

Share what we learn

Document the prototype, method, failures, and conclusions so the work can be challenged and extended.
